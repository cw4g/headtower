# Getting started

Headtower needs two things to come online: the URL of a reachable Headscale
instance, and an API key it can use to talk to it. Everything else is optional.

## Prerequisites

- A running **Headscale** control plane that Headtower can reach over the network.
- A **Headscale API key** (Headtower authenticates to the control plane with it).
- **Node.js 20+** and **pnpm** if you are running from source.

<Callout type="info">
  Generate an API key from your Headscale host with `headscale apikeys create`.
  Treat it like a password - it grants full control-plane access.
</Callout>

## Install and run

<Steps>

### Get the code

```bash
git clone https://github.com/rnihesh/headtower.git
cd headtower
pnpm install
```

### Set the environment

Headtower reads its configuration from the environment. Only two variables are
required to start:

```bash
export HEADSCALE_URL="https://headscale.example.com"
export HEADSCALE_API_KEY="<your-headscale-api-key>"
```

You can also drop these into a `.env.local` file at the project root.

### Start the console

```bash
pnpm dev
```

Open [http://localhost:3000](http://localhost:3000). Headtower opens on the
**Machines** readout - the core operational view.

</Steps>

<Callout type="warning">
  `HEADSCALE_URL` must be an `http(s)` URL and is normalized without a trailing
  slash. If either required variable is missing or malformed, Headtower fails
  loudly and names the offending variable rather than starting half-configured.
</Callout>

## Run with Docker

For a long-running deployment, run Headtower as a container and pass the same
environment in. A minimal `docker run` looks like:

```bash
docker run -d \
  --name headtower \
  -p 3000:3000 \
  -e HEADSCALE_URL="https://headscale.example.com" \
  -e HEADSCALE_API_KEY="<your-headscale-api-key>" \
  -v headtower-data:/data \
  -e HEADTOWER_DB_PATH="/data/headtower.db" \
  ghcr.io/rnihesh/headtower:latest
```

The bind-mounted volume keeps Headtower's own state (operators, roles, audit
log) across restarts. See [Configuration](/configuration) for the full set of
variables, including optional single sign-on.

<Callout type="info">
  Headscale remains the source of truth for tailnet data. The Headtower volume
  only persists Headtower-specific state, so it is safe to recreate the
  container as long as the volume is preserved.
</Callout>
